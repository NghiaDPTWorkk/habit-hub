Habit Tracker Pro — UI Mockups

Single-file clickable prototype rendered with Tailwind 3 (CDN). Doubles as the design source of truth for the 4-student team — every class used here is the same one to copy into frontend/src/.

📐 Design tokens

  • Emerald — success, completed, ACTIVE
  • Amber — warning, at-risk, PAUSED, MEDIUM priority
  • Rose — destructive, error, HIGH priority
  • Slate — neutrals, ARCHIVED, LOW priority
  • Violet — accent (Mindfulness category)
  • Indigo — accent (Study category)

🗂 Screen inventory

  1. Dashboard — FE-US-14, 23 · Core 4.1–4.8, Adv 6
  2. Habits list + filter sidebar — FE-US-06 · Core 1.6, 1.7, Adv 8.6
  3. New / Edit habit modal — FE-US-07 · Core 1.1–1.4, Adv 8.1, 8.2, 8.5
  4. Habit overflow menu — FE-US-08 · Core 1.5
  5. Quick check-in toggle — FE-US-09 · Core 2.2, 2.4
  6. Multi-count modal — FE-US-10 · Core 2.2, Adv 8.3
  7. Check-ins grouped-by-date — FE-US-11 · Core 2.3, Adv 8.7
  8. Goal panel — FE-US-12, 13 · Core 3.1–3.4, Adv 8.8
  9. Reset all data — FE-US-16 · Adv 7
  10. Toast catalogue — FE-US-15 · Adv 8.5
  11. Empty states — Adv 8.6, 8.7, 8.8
  12. Validation / error states — Adv 8.1–8.5
How to view: Just double-click index.html from Finder/Explorer — opens in any modern browser. Use the sticky nav bar at the top to jump between screens. Tailwind is pulled from a CDN; a working internet connection is required on first load.

12 · Validation & error states

PRPs: FE-US-15, FE-US-18 · Brief: Advanced 8.1–8.5

A8.1–A8.5 lifted into a single design surface. Inline form errors render directly under the offending field; service-level errors render as a toast (see Screen 10). The <ErrorState> shell is for catastrophic failures that abort the whole screen.

Inline field errors

Brief A8.1 · ZodError → AppError("ERR.HABIT.NAME_REQUIRED")

Brief A8.2 · ZodError → AppError("ERR.HABIT.TARGET_INVALID")

Brief A8.3 · service guard → AppError("ERR.CHECKIN.COUNT_EXCEEDS_TARGET")

Brief A8.4 · Zod refine → AppError("ERR.CHECKIN.FUTURE_DATE")
